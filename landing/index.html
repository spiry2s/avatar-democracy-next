How it works

Read, configure, then decide

  1. 01

    Read a bill

    The bill analyzer takes pasted text, a link from a supported official publisher, or a PDF. You get a plain-language summary and a section-by-section breakdown.

  2. 02

    Configure an Avatar

    In the closed demo, an invited person can set a coarse compass, write values, and name per-issue delegates. That setup is the instruction the Avatar follows.

  3. 03

    Review and override

    The Avatar can record a position from that configuration. The same person can change the setup or override a position. The record is there to be checked, not to stand in for the person.

What the bill analyzer does today

  • A plain-language summary and a section-by-section breakdown.
  • A quote for grounded claims. Section summaries, red flags, and beneficiary claims are treated as grounded only when a verbatim quote appears in the bill. If it does not, the claim is marked ungrounded and kept out of the Avatar. It is not presented as a verified finding.
  • An optional second reading from another provider. If you configure one, the same analysis runs again and the demo shows where the two readings differ. No third model picks a winner. The second reading is off unless you switch it on.

Citizen control

The person stays in charge

You choose the configuration. You can review the quote beside a claim, change delegates, leave an issue unset, or override a recorded position. The machine sits between that configuration and a demo record. It does not replace elections, representatives, or a parliament, and it does not take the place of a person's own judgment.

What belongs to the Avatar demo

The bill analyzer shows a reading. It does not cast a vote. On the separate Avatar demo, if two configured models disagree on a serious red flag, that section can be held as abstain so it adds neither a yes nor a no. That rule is not part of the general bill analyzer.

What you can run today

  • A local prototype: bill reading, one Avatar, a bill path, and a synthetic chamber. Start it from the repository with python main.py. Model calls need your own API key.
  • Quote checks, optional comparison, overrides, and an audit log, as implemented in the repository.
  • On this server, those pages stay behind an invite. Opening this page does not sign you in. An invite link is the way in.

Research and open questions

  • The white paper is a working document. Its open problems are listed in the paper.
  • Whether any jurisdiction ever gives an Avatar tally formal weight is a separate legal choice. This page does not make that choice.
  • Agreement between models is not proof. The synthetic chamber is a demo population, not real voters, and not a live vote count.

An honest note: this is an early prototype

  • The code runs locally (python main.py) and needs your own API key. The second-provider check is off unless you switch it on.
  • Language models can still misread legal text. A quote shows you where to look; it does not prove the summary is right. Always read the bill itself. This is not legal advice.
  • The Avatar, bill-lifecycle, and chamber pages are a demo. The chamber is a synthetic population, not real voters.
  • There are no adoption figures, endorsements, or accuracy scores on this page, because the project does not have them.

Nonpartisan by design

Avatar Democracy is not affiliated with, funded by, or run for any political party, candidate, or campaign. The analyzer's prompts tell it to avoid partisan framing and are published in the code for anyone to review. Any party may use the code under the MIT license, but none speaks for the project.

Help us find what is broken

If you study democratic institutions, machine-learning bias, verification, or law, or if you run participation programmes, send critique on GitHub Issues. Who can see that feedback depends on who can see the repository.
